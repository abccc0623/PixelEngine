# LLM Wiki

사람: 툴 설정 메뉴 → **LLM Wiki 검색**. 검색창 아래에 결과 수와 검색 시간이 표시됩니다.
AI: 기존 `search_wiki` / `Editor_Wiki_Search`의 `document`를 `*`로 지정합니다.
결과의 `wiki/...` 문서 ID는 기존 가이드 읽기 도구에서 사용할 수 있습니다. 별도 AI 호출이나 강제 선행 검색은 없습니다.

## 원본과 검색
- Tool의 `LLMWiki/API/Docs`: 엔진 API 설명의 원본과 배포본.
- `LLMWiki/API/Lua`: 엔진이 생성하는 실제 Lua 선언. LSP와 공유합니다.
- `LLMWiki/Skills`, `Rules`, `Knowledge`: 공통 스킬·규칙·지식 문서를 둘 수 있는 선택 폴더.
- 프로젝트별 새 기능 일감은 해당 프로젝트의 `Editor/WorkItems`에 저장합니다. 검색 화면은 현재 열린 프로젝트의 일감과 공통 문서를 함께 표시하지만, 일감 원본과 색인은 프로젝트마다 분리합니다.
- 게임 빌드는 `LLMWiki/API/Lua`만 복사합니다. Tool 문서와 프로젝트별 일감은 게임 빌드에 포함하지 않습니다.
- 문서 파일은 `.md`, `.txt`, `.lua`만 검색합니다. 원본 파일이 권위이며 SQLite나 모델 생성 요약은 사용하지 않습니다.
- Markdown 제목 `# 제목`, 문서 상단 40줄 이내 `aliases: 이동, movement`로 사람이 제목과 별칭을 등록할 수 있습니다.
- 정확한 파일명/제목 → 정확한 별칭 → 이름/제목 부분 일치 → 본문 구문 일치 → 모든 단어 일치 순입니다.
- 동점은 문서 ID 순으로 정렬합니다. 출처, 일치 행, 최대 240자 미리보기를 반환합니다. 스니펫만으로 문서 전체를 읽었다고 간주하지 않습니다.
- 규칙 문서 검색은 사용자 승인이나 실행 권한을 추가하지 않습니다.

## 갱신과 제한
검색마다 파일 목록·크기·수정 시간을 확인하며 바뀐 문서만 다시 읽습니다. 파일 추가/삭제는 다음 검색에서 반영됩니다.
파일 수정 시 정상적인 수정 시간 갱신이 필요합니다. 수정 시간과 크기를 의도적으로 동일하게 보존한 외부 변경은 Tool 재시작 전까지 감지되지 않을 수 있습니다.
파일당 1 MB, 총 64 MB, 최대 10,000개 문서 제한입니다. 제한 및 읽기 실패는 결과 상태에 표시됩니다.
연결 폴더/파일과 `..` 경로는 허용하지 않습니다. 검색은 순차이며 UI 스레드 밖에서 실행합니다.
입력 후 200 ms 대기하고 이전 요청은 취소합니다. 최신 검색만 UI에 적용됩니다.
표시 시간에는 파일 확인·갱신·검색·정렬이 포함되고 입력 대기·UI 표시는 제외됩니다.

## 검증
`PixelSolution/Tests/WikiSearch.Tests.ps1`: 정확도, 한국어/별칭, 안전 경로, 갱신, 취소, 동시 검색과 합성 3,000문서 성능 비교.
병렬 비교는 파일 로드가 아닌 메모리에 있는 텍스트 매칭만 비교하는 실험입니다. 실제 검색 경로는 순차를 유지합니다.
