# 파이프라인: 테스트

기능 구현을 마친 일감이나 직접 수정한 요청을 확인할 때 읽는다.

1. 구현한 일감의 완료 확인 항목을 하나씩 확인한다. 여러 객체의 동작을 구현하거나 구조를 바꿨다면 각 객체의 고유한 동작이 담당 스크립트에 있는지 소스로 확인한다.
2. 일감 구현을 마치면 MCP `reimport_project`로 에디터를 리프레시한다. 이 도구가 기존 로그를 비우므로 `clear_editor_logs`를 중복 호출하지 않는다. 반환된 새 로그에서 **에러를 먼저 확인**하고, 필요한 경우 `read_editor_logs`로 이후 로그를 이어 읽는다.
3. 에러 건수와 핵심 메시지를 먼저 확인한다. 에러가 있거나 로그가 잘렸을 때만 해당 구간과 남은 페이지를 자세히 읽는다. 파일명·발생 시각·원인을 확인한다. 리프레시나 로그 수집이 실패했다면 에러 없음으로 단정하지 않는다.
4. 여러 씬·스테이지를 구현했다면 시작 씬의 리임포트 로그만으로 끝내지 않는다. 수정한 각 씬에 **실제로 진입한 뒤** 그 시점 이후의 에러 로그를 확인한다. `set_editor_mode(play)`와 `test_game_key`로 도달할 수 있으면 전환 결과와 로그를 확인한다. 제한된 입력으로 도달할 수 없다면, 해시를 확인한 `Asset/main.lua`의 시작 씬만 임시로 대상 씬으로 바꾸고 리임포트해 검사한 뒤 원문을 복구하고 다시 리임포트한다. 임시 수정 전에 원문을 보관하고, 복구 실패 시 즉시 알린다. 어느 방법으로도 진입하지 못하면 해당 씬은 미확인으로 남긴다.
5. 에러가 없어도 기능 통과로 표시하지 않는다. 일감의 각 확인 항목은 실제 동작이나 관찰 가능한 테스트 로그로 따로 판정한다. 확인하지 못한 항목은 이유와 함께 미확인으로 남긴다. 이 테스트에서 플레이 모드로 전환했다면 종료 전에 원래 모드로 돌아간다.
6. 완료 확인 항목이 실패하면 해당 일감만 **버그수정**으로 분류해 `wiki/Skills/Pipeline/FeatureImplementation.md`로 돌린다. 기존 일감의 ID와 기획 목표를 유지하고, 실패 원인·수정할 결과·재확인 항목을 전달한다. 다른 일감은 다시 구현하지 않는다. 수정 후 이 일감만 재확인한다. 일감 없이 직접 수정한 요청도 실패한 결과만 버그수정으로 다시 다룬다.

확인 결과를 `wiki/Skills/Pipeline/Completion.md`로 넘긴다. 미확인 항목은 통과로 표시하지 않는다.
