# 파이프라인: 요청 분석

파이프라인을 실행할 때 첫 단계에서 읽는다.

1. 사용자의 요청이 무엇인지 파악하고, 원하는 결과를 짧게 정리한다.
2. 관련 파일과 기존 동작을 확인한 뒤 **원인조사**, **버그수정**, **기능변경**, **코드개선**, **신규구현** 중 하나로 판단한다. 여러 목적이 섞여 있으면 각각 적는다.
   **코드개선**에는 기존 동작을 유지하며 구조·가독성·성능을 개선하는 리팩터링을 포함한다.
3. 확인 전에는 유형을 확정하지 않고 **잠정**으로 표시한다. 근거가 부족하면 확인할 파일·동작을 남긴다. 예를 들어 “Player의 속도를 5로 변경”은 기존 값이 다르면 기능변경, 속도 기능이 없으면 신규구현, 이미 5면 변경할 일이 없다.

다음 단계에는 요청 내용, 확인한 근거, 판단한 유형을 전달한다. **신규구현**으로 확인되면 `wiki/Skills/Pipeline/WorkItemCreation.md`를 읽고 일감생성 단계로 넘어간다. 이 단계에서 작업 크기나 담당자는 정하지 않는다.
