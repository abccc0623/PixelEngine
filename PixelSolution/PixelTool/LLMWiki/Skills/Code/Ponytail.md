# Ponytail: 코드 작업용 최소 구현 원칙

코드를 추가·수정할 때 한 요청에서 한 번 읽는다. 이후 같은 작업의 재시도에는 다시 읽지 않는다. 설명·조사·일감 작성만 할 때는 적용하지 않는다. 사용자가 중단을 요청하면 적용하지 않는다.

1. 요청과 현재 코드의 호출 경로를 이해한 뒤, 이미 있는 기능 → 표준 라이브러리 → 플랫폼 기본 기능 → 설치된 의존성 순으로 재사용한다. 그래도 필요할 때만 최소 코드를 작성한다.
2. 버그는 증상이 아닌 공통 원인을 고친다. 불필요한 추상화·의존성·미래 대비 코드는 추가하지 않는다. 관련 없는 기존 코드는 보존한다.
3. 입력 검증, 데이터 손실 방지, 보안, 사용자가 요구한 동작과 필요한 검증은 줄이지 않는다. 새 분기·반복 등 의미 있는 로직은 가장 작은 실행 가능한 검사로 확인한다.
4. 결과는 실제 수정과 검증만 간단히 보고한다. 구현 방식은 이 문서보다 사용자 요청, 호스트 권한, 프로젝트 파이프라인 규칙을 우선한다.
