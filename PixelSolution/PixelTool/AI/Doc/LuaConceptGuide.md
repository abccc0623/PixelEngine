# Lua API 개념과 동작 규칙

이 문서는 배포된 PixelTool AI가 Lua API의 공통 동작을 이해할 때 읽는다. API 이름과 문서 위치는 `LuaApiIndex.md`에서 찾는다. 정확한 매개변수·반환값은 현재 열린 프로젝트의 `Engine/*.lua` 선언으로 확인한다. 선언, 성공한 리임포트, 실제 실행 검증은 서로 다르다. 엔진 DLL 내부를 추측하거나 수정하지 않는다.

## 실행 흐름과 객체 수명

- 엔진은 `Asset/main.lua`를 읽고 전역 `Main()`을 호출한다. Scene 파일을 가져오기만 해서는 실행되지 않으며, `Scene.Change`로 선택해야 한다.
- 모든 Entity는 Scene에 속한다. Scene을 바꿔도 기존 객체가 자동 이동하지 않는다. Scene의 `Start`는 전환 시 실행되지만 Lua `Release` 호출은 현재 비활성화되어 있다.
- 스크립트가 연결된 객체를 생성하면 `Spawn()`이 반환 전에 한 번 실행된다. 풀에서 재사용할 때는 다시 실행되지 않는다. 객체의 기본 필드와 컴포넌트는 해당 스크립트의 `Spawn()`에서 준비한다.
- `Entity.CreateCamera()`는 ID, `Entity.Create2DImage()`는 UIImage 데이터처럼 생성 도우미마다 반환 종류가 다르다. ID, Lua 스크립트 테이블, 컴포넌트 데이터를 혼동하지 않는다.
- 객체 파괴 후 ID·테이블·컴포넌트 참조가 남아 있는지 확인한다. 비활성화는 삭제가 아니다. 비활성 객체의 Lua Update와 ECS 충돌·애니메이션은 중단된다.

## 불러오기와 Lua 작성

- `Asset.Import`는 파일 또는 폴더를 가져온다. 전역 데이터, 스크립트, 객체 생성의 순서를 명시하고, 폴더 내부 탐색 순서가 의존성을 해결한다고 가정하지 않는다.
- 게임 스크립트에 중복 `require`·`dofile`·`loadfile` 로더를 추가하지 않는다. 엔진 내부의 필요한 `require("ffi")`는 제거하지 않는다.
- 새 객체 스크립트는 에디터 템플릿의 순서와 초기화·주석을 따른다. 객체별 기본값은 파일 최상위나 생성하는 Scene 대신 `Spawn()`에 둔다.
- 함수와 블록을 한 줄로 축약하지 않는다. 함수 역할 주석은 정확하게 적고, 무관한 코드를 재포맷하지 않는다. 전역 편집용 데이터는 `Asset/Table/`에, 객체별 데이터는 그 객체 스크립트에 둔다.
- 콜론 호출은 `self`를 전달한다. 일반 Lua 배열은 1부터 시작하지만 일부 엔진 API 인덱스는 0부터 시작한다. 명확한 문법 오류만 허용 범위에서 고치고 다른 로직 변경은 요청 범위를 확인한다.

## 컴포넌트와 좌표

- 컴포넌트의 `Add(ID)`와 `Get(ID)`는 ID가 아닌 컴포넌트 데이터를 반환하고, `Has(ID)`는 존재를 확인한다. 데이터 메서드는 콜론으로 호출한다. 세부 기능은 `LuaApiIndex.md`에서 해당 컴포넌트 문서를 찾는다.
- 월드 이미지는 `Renderer2D`, 화면 UI는 `UIImage`·`UIText`를 사용한다. UI는 창 해상도와 별개의 1920×1080 가상 캔버스를 사용하며 원점은 왼쪽 위다. UI 피벗은 0~1 범위다.
- 창 크기 변경은 가상 캔버스 경계를 바꾸지 않으며 PixelTool에서는 무시된다. 부모·자식 Transform, 로컬·월드·화면 좌표를 구분한다.
- 렌더러와 UI 색상 RGBA는 0~255 범위다. 컴포넌트별 필드와 주의사항은 각 문서에서 확인한다.

## 시간·재사용·물리

- 게임 일시정지 중 `GetDeltaTime()`과 `Update(DTime)`의 시간 값은 0이다. 활성 객체에는 Update가 계속 호출될 수 있다. 비시간 기반 로직은 자동 정지하지 않는다. Unscaled 시간과 `GetTotalTime()`은 계속 진행한다.
- 같은 객체·속성에 새 Tween을 시작하면 기존 Tween을 교체한다. 다른 속성은 공존한다. `PingPong`의 Duration은 한 방향의 시간이고, Kill은 현재 값을 유지한다. 객체 비활성화는 진행을 멈추고 재활성화는 재개한다.
- Pool과 Group은 현재 Scene에 속한다. Pool 재사용 시 위치·체력 같은 게임 상태를 다시 설정한다. 두 그룹의 ID 조회 인덱스는 0부터 시작한다. 목록을 순회하며 반환하면 항목을 건너뛸 수 있다. Clear는 객체 파괴를 뜻하지 않는다.
- `Animation2D`만으로는 화면에 보이지 않는다. 애니메이션·프레임 인덱스는 0부터 시작한다. 프레임 속도를 애니메이션 전체 지속 시간으로 단정하지 않는다.
- Rigidbody2D의 Transform 변경이 물리 위치에 그대로 반영된다고 가정하지 않는다. Lua 충돌 콜백은 상대 ID를 받으며 접촉 법선은 제공하지 않는다. 등록된 메서드라도 네이티브 본문이 비어 있으면 구현된 기능으로 취급하지 않는다.

## 확인과 진단

- `Input.Key`, `KeyDown`, `KeyUp`은 유지·누름·뗌을 구분한다. 키는 문자열이나 Windows 가상 키 번호가 아닌 현재 프로젝트의 `Keycode` 선언으로 확인한다.
- 마우스 입력 좌표를 월드나 부모 기준 UI 좌표로 가정하지 않는다. 이벤트 바인딩은 함수 이름 문자열을 사용한다.
- 로그에는 현재 등록된 `Debug.Log`, `LogWarning`, `LogError`를 쓴다. 로그와 리임포트 성공만으로 게임 동작이나 화면 결과를 단정하지 않는다.
- 현재 프로젝트 선언과 이 문서가 다르면 프로젝트 버전의 실제 선언을 우선 확인하고 차이를 알린다.
