## 상황
프로젝트 시작 스크립트를 다시 만들어 보고 싶어서 `Create > Main Lua File`을 눌렀다. 이미 `main.lua`가 있는 상태라면 보통은 생성 취소, 다른 이름 저장, 백업 생성 같은 선택지를 기대하게 된다.

## 문제
`ToolbarWindow.xaml.cs`는 파일이 이미 있으면 `기존 main파일을 삭제 하겠습니까?`라고 물어본 뒤, 사용자가 Yes를 누르면 삭제 과정 없이 곧바로 같은 경로에 `File.WriteAllText`를 호출해 내용을 덮어쓴다. 문구는 삭제 확인처럼 보이는데 실제 동작은 즉시 덮어쓰기라서, 기존 스크립트에 남아 있던 초안이나 임시 코드가 복구 경로 없이 사라질 수 있다.

## 제안
이 흐름은 최소한 `덮어쓰기`로 문구를 정확히 바꾸고, 가능하면 `.bak` 백업이나 날짜 접미사 파일을 남기는 쪽이 안전하다. 더 나아가면 기존 파일을 열어서 비교한 뒤 새 템플릿을 다른 이름으로 생성하는 선택지를 주는 편이 초기 프로젝트 스크립트 실험에 훨씬 덜 위험하다.
