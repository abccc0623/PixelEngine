## 상황
PixelTool에서 씬 뷰만 띄워 둔 채 Lua를 수정하거나 다른 창에서 작업할 때 에디터가 가만히 있어도 팬이 계속 도는지 확인하려고 `PixelTool/Tool/GraphicsWindow/GraphicsWindow.cs`를 읽었다. 편집기 안에서 게임을 계속 움직이지 않는 시간도 길기 때문에, 유휴 상태에서 엔진 갱신이 어떻게 돌아가는지가 체감 성능에 바로 영향을 준다.

## 문제
`GraphicsWindow.EngineLoop()`는 `_isRunning`이 true인 동안 아무 대기 없이 `PixelEngineNative.UpdateEngine()`를 계속 호출한다. 별도 프레임 제한이나 창 비활성 상태 감속이 없어서, 실제로는 사용자가 Lua 코드만 읽고 있어도 렌더 스레드가 CPU 시간을 계속 점유하는 구조다. 에디터를 오래 켜 두고 문서나 코드 작업을 병행할수록 배터리와 발열 부담이 커지고, 지금 병목이 엔진인지 툴인지 체감으로 분리하기도 어려워진다.

## 제안
기본적으로는 목표 프레임에 맞춘 대기나 `Sleep(0)` 이상의 양보 지점을 넣고, 창 비활성화나 최소화 상태에서는 갱신 빈도를 낮추는 흐름이 있으면 좋겠다. 최소한 디버그 로그나 상태 표시로 현재 에디터가 유휴 렌더링 중인지 보이면, 엔진 작업 중 리소스 사용을 해석하기가 훨씬 쉬워진다.
