## 상황
에디터가 아닌 `Client` 실행 파일로 바로 런타임을 띄워 보는 흐름을 가정하고 `PixelSolution/Client/main.cpp`를 읽었다. 엔진 쪽 문제를 분리하려고 최소 실행 경로만 열어 보는 경우, 첫 프레임 전에 어떤 스크립트가 준비돼 있어야 하는지 안내가 분명해야 바로 테스트를 이어갈 수 있다.

## 문제
현재 `main()`은 창을 띄운 뒤 바로 `Import("./Asset/main.lua")`를 호출하지만, 그 전에 파일 존재 여부나 실패 이유를 사용자 흐름에 맞게 설명하는 단계가 없다. 기본 스크립트가 없거나 작업 디렉터리가 다르면 실행은 됐는데 아무것도 안 보이는 상태처럼 느껴질 수 있고, 사용자는 엔진 초기화 문제인지 Lua 진입 파일 문제인지부터 다시 추적해야 한다.

## 제안
시작 전에 `./Asset/main.lua` 존재를 확인하고, 없으면 경로와 기대 파일명을 명확히 로그나 메시지로 남겨 주면 좋겠다. 가능하면 실행 인자나 설정 파일로 시작 스크립트를 바꿀 수 있게 해 두면, 클라이언트 단독 테스트와 여러 샘플 스크립트 전환이 훨씬 편해진다.
