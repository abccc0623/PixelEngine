## 상황
Lua 파일 두세 개를 번갈아 수정하다가 Asset 창에서 다른 스크립트를 열 때 저장 확인이 어떻게 뜨는지 보려고 `PixelTool/Tool/EditorLuaWindow/LuaEditor.xaml.cs`의 `OpenFile` 흐름을 읽었다. 실제 작업에서는 아직 실험 중인 수정은 잠시 보류하고 다른 파일을 먼저 확인하고 싶은 경우가 자주 생긴다.

## 문제
현재 파일이 더럽혀진 상태에서 다른 파일을 열면 `PixelMessageBox.Show(..., YesNo)`만 띄우고, `Yes`면 저장 후 진행하고 `No`면 그대로 새 파일을 연다. 즉 `No`가 사실상 "저장하지 않고 버리기"인데, 취소해서 현재 파일에 남아 있을 선택지가 없다. 사용자는 단순히 지금 저장만 미루고 싶었을 뿐인데, 한 번 잘못 누르면 수정 내용이 바로 사라질 수 있다.

## 제안
저장 확인을 `저장 / 버리기 / 취소` 3단계로 나누고, 최소한 `No` 버튼 문구를 버리기 의미로 분명히 드러내면 좋겠다. 파일 전환은 에디터에서 가장 자주 일어나는 동작이라, 이 단계가 명확해야 Lua 스크립트 실험과 비교 작업을 덜 긴장하고 할 수 있다.
