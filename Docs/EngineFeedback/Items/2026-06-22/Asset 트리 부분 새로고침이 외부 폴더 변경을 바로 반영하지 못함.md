## 상황
탐색기나 Git 작업으로 `Asset` 아래 폴더를 바꾼 뒤 PixelTool로 돌아와 현재 폴더만 다시 읽는 상황을 떠올리며 `PixelTool/Tool/AssetWindow/AssetWindow.xaml.cs`의 새로고침 경로를 확인했다. 에셋 정리는 에디터 바깥 도구와 병행하기 쉬워서, 내부 트리와 실제 디스크 구조가 금방 어긋날 수 있다.

## 문제
우클릭 메뉴의 `RefreshFolder`는 `SelectFolder(nowFolder.fullPath)`만 호출해서 오른쪽 파일 목록만 다시 읽고, 왼쪽 폴더 트리는 다시 스캔하지 않는다. 그래서 외부에서 하위 폴더를 추가하거나 이름을 바꿨을 때, 사용자는 새로고침을 눌렀는데도 트리에는 변화가 안 보여 구조가 반영되지 않은 것처럼 느끼게 된다. 전체 새로고침을 따로 알아야만 실제 상태를 다시 맞출 수 있는 점이 작업 흐름을 끊는다.

## 제안
현재 폴더 새로고침에서도 최소한 해당 경로 아래 트리를 다시 스캔하거나, "파일만 새로고침"과 "트리 포함 새로고침"을 구분해 주면 좋겠다. 외부 변경이 잦은 에셋 폴더에서는 지금 내가 보고 있는 구조가 실제 디스크와 같은지 바로 신뢰할 수 있어야 한다.
