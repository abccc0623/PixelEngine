## 상황
실행 중인 프로젝트에서 텍스처나 Lua 파일의 이름을 바꾸거나 폴더를 옮겼을 때 에디터와 런타임이 같이 따라오는지 보려고 `PixelTool/Tool/AssetWindow/AssetWindow.xaml.cs`의 파일 조작 경로를 읽었다.

## 문제
`RenameFile()`, `TransferPaths()`, `DuplicateFile()`, `CopyExternalFile()`는 디스크상의 파일만 `Move`, `Copy`, `Delete`로 바꾸고 목록만 `Refresh()`한다. 하지만 이 경로들 어디에서도 `PixelEngineNative.Import(...)`나 기존 리소스 무효화에 해당하는 호출이 없어, 실행 중 엔진은 예전 경로나 예전 리소스 키를 계속 잡고 있을 가능성이 크다. 사용자는 Asset 창에서 분명히 이름을 바꿨는데 플레이 상태나 미리보기 쪽 반응은 늦거나 어긋나서, 무엇이 편집 상태이고 무엇이 런타임 상태인지 헷갈리기 쉽다.

## 제안
에셋 이름 변경, 이동, 복제, 외부 파일 복사 직후에 파일 종류별 runtime 갱신 경로를 명시적으로 연결하면 좋겠다. 최소한 현재 동작이 디스크 반영만 하는지, 엔진 리소스까지 다시 읽는지 로그나 안내를 남겨서 편집 결과의 반영 범위를 분명히 보여줘야 한다.
