## 상황
그래픽 초기화가 특정 PC나 원격 환경에서 실패했을 때 WARP 같은 대체 경로가 준비되어 있는지 확인하려고 `GraphicsCore::GraphicsInitialize()`의 드라이버 선택 코드를 읽었다.

## 문제
코드에는 `D3D_DRIVER_TYPE_HARDWARE`, `WARP`, `REFERENCE` 세 가지 후보 배열이 선언되어 있지만, 실제 루프 조건이 `driverTypeIndex < 1`로 고정되어 있어서 첫 번째 하드웨어 타입만 시도한다. 주석과 배열 구조만 보면 실패 시 다음 타입으로 넘어갈 것 같지만, 실제로는 fallback이 없어서 개발자는 드라이버 호환 문제를 더 거칠게 맞닥뜨리게 된다.

## 제안
루프가 실제 후보 개수 전체를 돌도록 맞추고, 어떤 드라이버 타입에서 성공했는지 로그를 남기면 좋겠다. 그러면 GPU가 없는 테스트 환경이나 원격 세션에서도 최소한 에디터 그래픽 경로를 살려 둘 수 있고, 실패 원인도 더 빨리 좁힐 수 있다.
