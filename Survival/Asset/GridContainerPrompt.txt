다른 AI에게 전달할 Grid 컨테이너 재구현 프롬프트

아래 사양을 기준으로 기존 프로젝트의 구조와 API를 먼저 확인한 다음 구현해 주세요. 이 문서는 현재 Survival 프로젝트의 구현을 기준으로 한 동작 명세입니다. 엔진별 객체 생성, UI, 벡터, 시간 API는 해당 프로젝트에서 실제 제공하는 것을 사용하세요. 제공되지 않는 API를 만들어내지 마세요. 다음 요구사항에 없는 자동 정체 해소, 자원 삭제, 우회, 순환 차단은 추가하지 마세요.

목표
12×12 칸에 설치된 길을 방향이 연결된 운송 그룹으로 묶고, 각 자원을 개별 물리 이동 판정하는 대신 그룹의 선두 거리와 자원 간 간격으로 관리하는 2차원 Grid 컨테이너를 구현한다. 편집·회전 후에도 기존 자원을 최대한 보존하고 테스트용 시뮬레이션은 실제 게임 상태와 분리한다.

1. Grid 데이터
- Grid.width = 12, Grid.height = 12. 인덱스는 1부터 시작하며 Grid[x][y]로 접근한다.
- 각 셀은 ItemIndex, ID, Script, RoadGroup을 가진다. 빈 셀의 ItemIndex는 -1이고 객체와 스크립트는 nil이다.
- 1은 Road, 2는 BasicInput(생성점), 3은 BasicOutput(도착점)이다. 다른 유효한 아이템은 일반 설치 객체로 생성할 수 있다.
- Grid.BoardID는 보드 객체이며 각 타일과 자원 표시 객체는 보드의 자식이다. 240×240 로컬 좌표의 중심을 원점으로 삼는다. 셀 중심은 x=-120+(열-0.5)*240/12, y=-120+(행-0.5)*240/12다.
- 셀 좌표가 숫자이고 정수이며 범위 안에 있는지 확인한다. 설치 또는 삭제·회전 후 길 그룹과 자원 연결을 갱신한다. 전투 중 편집 잠금, 편집 중 수정 허용.

2. 길 방향과 그룹화
- 길은 각 칸 기준 상하좌우 단위 벡터 Input과 OutPut을 가진다. 기본 Input=(-1,0), OutPut=(1,0). 회전은 두 벡터에 (-y,x)를 적용한다.
- 그룹 재구성 전에 각 길의 출력을 유지하면서 이웃 장치의 출력이 해당 칸을 향하는 후보를 조사한다. 길 자신의 출력 쪽 이웃은 후보에서 제외한다. 기존 입력이 후보 중 하나면 유지하고, 그렇지 않으면 후보가 하나일 때 그 방향을 입력으로 한다. 후보가 없거나 여러 개면 출력의 반대 방향을 입력으로 한다.
- 인접 길 둘은 한쪽 출력과 다른 쪽 입력이 서로를 정확히 향할 때만 같은 그룹이다. 상하좌우를 순회하며 연결된 길을 수집하고 각 셀 및 길 스크립트에 같은 그룹 참조를 기록한다.
- 그룹의 각 타일은 x,y,ID를 가진다. 입력 방향에 연결된 이전 길이 없는 타일에서 시작하여 출력 방향을 따라 정렬한다. 시작점이 없으면 순환 그룹으로 표시하고 임의의 첫 타일에서 방문한 타일까지 순회한다.
- 재구성 전에 기존 그룹을 비활성화하고 기존 셀의 그룹 참조를 제거한다. 정렬된 타일로 새 경로를 생성한 뒤 전체 자원을 재연결한다.
- 직선·양쪽 코너 이미지는 입력과 출력 조합으로 결정하며 출력 방향에 맞춰 회전한다.

3. 경로 표현
- 한 타일의 입력 경계 → 중심 → 출력 경계를 각각 직선 구간으로 만든다. 각 구간에는 시작·끝 좌표, 길이, 그룹 시작점부터의 누적 거리, 타일 좌표를 둔다. 타일별 구간 목록도 둔다.
- 순환하지 않는 그룹의 첫 입력과 마지막 출구는 자원 크기의 절반만큼 경계 안으로 들인다. 그룹은 시작점 input, 마지막 Output, Length, Segments, TileSegments를 가진다. 순환 그룹의 input과 Output은 nil이다.
- 경로 거리에서 위치를 구할 때 순환은 전체 길이로 나머지를 취하고 비순환은 0~Length로 제한한다. 누적 거리로 구간을 찾고 선형 보간하여 위치 및 타일을 구한다.

4. 그룹 자원 컨테이너와 생산
- 기본값: 이동 속도 20 로컬 픽셀/초, 최소 중심 간격 6, 자원 크기 4, 생산 간격 1초, 자원 종류 1.
- 그룹은 Resources(선두부터 순서대로), Gaps(이웃 간 거리), HeadDistance, TailDistance, CompressIndex를 저장한다. 전체 자원 목록도 별도로 보관한다.
- 자원의 거리 = HeadDistance에서 앞선 Gaps를 순서대로 뺀 값이다. 표시 위치는 이 거리로 경로를 조회해 갱신한다.
- 생성점은 출력 방향의 인접 길에 1초마다 투입을 시도한다. 실패한 생산을 대기열에 쌓지 않는다. 길이 없거나 자원 종류가 없거나 인접한 투입 위치에 최소 간격이 확보되지 않으면 실패한다.
- 임의의 길 칸 및 인접한 진입 측을 지정해 투입할 수 있다. 진입 측에서 타일 중심까지 별도의 직선 Entry 구간을 이동한 뒤 본 경로를 따른다. 다른 그룹에서 넘어오는 자원은 기존 표시 위치에서 시작하며 객체를 재생성하지 않는다.
- 기존 자원들과의 경로상 거리가 최소 간격보다 작으면 투입하지 않는다. 순환 경로에서는 양 방향 중 짧은 원형 간격을 사용한다. 삽입 후 선두부터 거리 내림차순으로 정렬하고 Gaps, HeadDistance, TailDistance를 갱신한다.

5. 이동, 정체, 합류, 회수
- 각 틱 처리 순서는 모든 생성점 생산 → 모든 그룹 이동 → 그룹 간 이송 → 모든 도착점 회수다. 모든 그룹을 먼저 이동시킨 후 이송하여 같은 틱에 그룹 순서 때문에 두 번 이동하지 않게 한다.
- 비순환 그룹은 선두를 최대 속도로 출구까지 이동한다. 선두가 막히면 남은 이동량으로 선두 뒤 간격부터 차례로 최소 6까지 압축한다. 이미 압축된 간격은 CompressIndex로 건너뛴다. 더 이상 간격이 줄지 않으면 뒤 자원도 정지한다.
- 순환 그룹은 선두 거리를 길이로 나머지 처리하고 선두·후미의 간격을 유지하며 돈다. 빈 공간이 없다는 이유로 자원을 제거하거나 루프를 깨지 않는다.
- 비순환 그룹의 선두가 출구에 도착하면 출력 방향의 다른 길 그룹에 전달을 시도한다. 측면 합류는 허용하되 두 길의 출력이 서로 정면으로 마주보는 역방향 연결은 거절한다. 공간이 부족하거나 연결이 없으면 자원을 유지해 정체를 전파한다.
- 도착점은 자신의 입력 방향에 있는 길의 출력이 도착점을 향할 때, 해당 길이 그룹의 마지막 타일이고 선두가 출구에 도착했다면 선두 자원을 회수한다. 전체 목록에서도 제거하고 표시 객체를 정리한다. 회수 후 효과는 별도 확장 지점이며 현재 기준으로 비어 있다.

6. 편집과 재연결
- 편집 시작 시 실제 전체 자원, 그룹별 Resources/Gaps/선두·후미 거리/압축 인덱스, 생성점 경과 시간을 보관한다. 실제 자원 객체를 비활성화하고 테스트용 빈 컨테이너를 사용한다.
- 테스트는 게임 일시정지 중에도 비정지 델타 시간으로 진행한다. 테스트 중단 또는 길 변경 시 테스트 자원을 제거한다.
- 편집 종료 시 테스트 자원을 정리하고 실제 자원을 복원한다. 그룹이 그대로면 저장한 그룹 상태를 되돌리고, 그룹이 바뀌었다면 자원의 기존 타일에 속하는 새 구간에 기존 위치를 투영해 재연결한다.
- 재연결할 때 거리 내림차순으로 정렬하고 최소 간격과 경로 수용량을 고려한다. 진입 중 자원은 현재 위치에서 타일 중심까지의 Entry를 다시 만든다. 새 경로가 없거나 수용량이 부족한 자원은 삭제하지 않고 기존 위치에 별도로 남겨 다음 길 수정 시 다시 편입할 수 있게 한다.
- 실제 생성점의 경과 시간도 복원한다. 테스트가 실제 진행 상태를 바꾸지 않아야 한다.

7. 화면과 초기 상태
- 같은 보드와 자식 객체를 유지하면서 전투 중 보드는 좌상단 240×240, 여백 24로 표시한다. 편집 시에는 보드의 최상위 위치·배율을 책의 왼쪽 페이지에 맞춘다.
- 초기 배치는 (6,1) 생성점, (6,2)~(6,11) 아래 방향 길, (6,12) 도착점이다. 모든 방향과 배치를 적용한 뒤 그룹을 재구성한다.

8. 수용 기준
- 직선, 코너, 단절된 길을 방향에 따라 올바르게 그룹화하고 역방향으로 맞댄 출력은 전달하지 않는다.
- 자원이 직선·코너를 연속적으로 이동하며, 측면 합류 시 경계에서 중심까지 이동하고 기존 자원과 최소 간격을 유지한다.
- 출구가 막히면 자원은 순서대로 밀집하고 생산은 공간이 생길 때만 성공한다. 자원이 자동 삭제되거나 우회하지 않는다.
- 순환 경로의 시작 경계를 넘어도 위치와 간격이 유지된다.
- 여러 그룹이 연결돼도 한 틱에 자원이 두 그룹의 이동량을 중복 적용받지 않는다.
- 편집 테스트 시작·중단·복귀가 실제 자원의 수량과 생산 경과 시간을 훼손하지 않는다.
- 길 삭제·회전 후에도 자원은 재연결되거나 원래 위치에 보존된다. 생성점과 도착점의 방향이 맞지 않으면 투입 또는 회수가 발생하지 않는다.
- 실제 프로젝트의 API와 객체 수명 규칙을 확인하고 적용한다. 동작 확인이 불가능하면 정적 확인과 실행 검증의 차이를 명시한다.

참고 원본: Asset/Script/Build/Grid.lua, RoadTransport.lua, BuildSystem.pxm, Road.pxm, BasicInput.pxm, BasicOutput.pxm. 프롬프트만으로 모든 경계 상황에서 원본과 완전히 동일함을 보장할 수 없으므로, 정확한 복제가 필요하면 이 원본과 비교한다.
