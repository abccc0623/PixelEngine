# Survival 클라이언트 게임 용어

- 게임 콘텐츠의 작업 경로는 `D:\PixelEngine\Survival`, 주로 `Survival\Asset`이다.
- **플레이 모드**: 사용자가 직접 키보드로 캐릭터를 이동시키며 플레이하는 모드다.
- **Grid 설치 모드**: 캐릭터가 레벨업한 뒤 아이템을 설치하는 모드다. 플레이 모드와 구분해서 설명하고 작업한다.
- **설치 종류 아이템**: 아이템 리스트에서 설치 종류에 해당하는 아이템은 모두 자원을 변경시키는 장치다. 자원 자체나 플레이어에게 직접 적용되는 능력치 아이템과 구분한다.
- 이 명칭을 기존 코드의 함수명·상태명에 연결할 때는 실제 구현을 확인한다. 용어를 정리했다는 이유만으로 기존 코드나 게임 동작을 변경하지 않는다.

## 클라이언트 Lua 작성 형식

- 엔진이 Asset 폴더와 하위 폴더의 파일을 자동으로 로드하므로 클라이언트 Lua에 `dofile`로 파일을 다시 불러오는 코드를 추가하지 않는다. 기존 자동 로드 흐름을 사용한다.
- 사용자가 별도로 엔진 없는 독립 테스트를 요청하지 않았다면 `dofile` 기반 테스트 파일이나 로더도 새로 추가하지 않는다. 기존의 무관한 테스트 파일을 일괄 변경하거나 삭제하지 않는다.

- 클라이언트 Lua 로직의 `if`/`elseif`/`else`, `for`, `while`, `repeat`, 함수 등 블록은 한 줄로 축약하지 않는다. 조건/선언, 본문, 종료 구문을 각각 다른 줄에 쓴다. 조기 반환도 동일하다.
- 블록 본문은 중첩 깊이마다 실제 탭 한 개로 들여쓴다. 함수 호출 자체의 인수는 가능한 한 한 줄로 유지한다.
- 이 규칙을 적용하려고 요청 범위 밖의 기존 파일을 일괄 재포맷하지 않는다.

```lua
if Grid.BoardID then
	Entity.CallFunction(Grid.BoardID,"Draw")
end
```

## 구현 중 질문

- 구현 요청을 받았을 때 동작·수치·적용 범위 등 결과에 영향을 주는 의문이나 불명확한 요구가 생기면 즉시 사용자에게 질문한다. 임의로 결정한 뒤 구현을 끝내고 뒤늦게 확인하지 않는다.
- 작업 도중 새 의문이 생겨도 그때 바로 질문한다. 답변이 필요한 부분은 보류하고, 답변과 무관하게 확정된 부분만 진행한다.
- 기존 코드나 파일에서 확인할 수 있는 내용은 먼저 확인하고, 이미 답변받은 사항을 반복해서 묻지 않는다.
